# 编译命令总结

本文只描述当前 BSP 脚本体系。路径示例使用占位符，不写真实主机目录：

```bash
cd <workspace>
NFS_DIR=<nfs-dir> TFTP_DIR=<tftp-dir> ./buildscripts/<script>.sh
```

## 快速决策表

| 我改了什么 | 推荐命令 | 结果 |
| --- | --- | --- |
| 只改 DTS/DTSI | `./buildscripts/dtb.sh` 或 `./buildscripts/build_and_deploy.sh dtb` | 只部署 `imx6ull-friedegg-emmc.dtb` 到 TFTP |
| 只改 Linux 非 DTS 源码或内核配置已生效 | `./buildscripts/linux_rebuild.sh` 或 `./buildscripts/build_and_deploy.sh zimage` | 执行 Buildroot `linux-rebuild`，只部署 `zImage` 到 TFTP |
| 只改一个 BSP local 包的 `.ko`、测试程序或 Qt demo | `./buildscripts/pkg_redeploy.sh <pkg>` 或 `./buildscripts/build_and_deploy.sh drv <pkg>` | 包级 dirclean + 重编，只把该包文件增量复制到 NFS |
| 包文件被删除、重命名或临时禁用后要清 NFS 旧文件 | `./buildscripts/pkg_clean_stale.sh <pkg>` | 按上次部署 manifest 删除该包不再拥有的 NFS 文件 |
| 改 BusyBox、Buildroot package、rootfs overlay，想重新铺 NFS | `./buildscripts/rootfs_redeploy.sh` 或 `./buildscripts/build_and_deploy.sh rootfs` | 生成 `rootfs.tar`，清空 NFS rootfs 后解包 |
| 配置或输出目录可能残留，想最干净重来 | `./buildscripts/all_rebuild.sh` 或 `./buildscripts/build_and_deploy.sh all` | 重读 BSP 固化配置，`make clean && make`，全量部署 TFTP/NFS |
| 改了 Buildroot/BusyBox/Linux menuconfig，要固化或回滚 | `./buildscripts/config.sh status|save|reset ...` | 管理 `bsp/configs/` 中三类固化配置 |

兼容入口仍保留：

```bash
./buildscripts/build_and_deploy.sh all
./buildscripts/build_and_deploy.sh dtb
./buildscripts/build_and_deploy.sh zimage
./buildscripts/build_and_deploy.sh linux-rebuild
./buildscripts/build_and_deploy.sh rootfs
./buildscripts/build_and_deploy.sh drv <pkg>
./buildscripts/build_and_deploy.sh drv add <pkg> <src-dir> [app-bin]
./buildscripts/build_and_deploy.sh drv list
./buildscripts/build_and_deploy.sh config status
```

旧校验子命令已删除；兼容入口遇到该旧子命令会按未知命令处理。

## 共享边界

所有编译部署脚本共用 `buildscripts/lib/common.sh`：

- 工作区：`<workspace>`
- BSP external：`<workspace>/bsp`
- Buildroot：`<workspace>/buildroot`
- Buildroot 输出：`<workspace>/buildroot/output`
- 默认 DTB：`imx6ull-friedegg-emmc.dtb`
- 默认内核镜像：`zImage`
- 默认部署变量：`NFS_DIR=<nfs-dir>`、`TFTP_DIR=<tftp-dir>`、`MAKE_JOBS=<n>`

Buildroot 调用统一携带：

```bash
BR2_EXTERNAL=<workspace>/bsp
BR2_PACKAGE_OVERRIDE_FILE=<workspace>/bsp/local.mk
BR2_JLEVEL=$MAKE_JOBS
BSP_KERNEL_CROSS_COMPILE=<old-kernel-toolchain-prefix>
```

`BR2_EXTERNAL` 让 Buildroot 读取 `bsp/Config.in`、`bsp/external.mk`、`bsp/package/` 和 `bsp/configs/`。`BR2_PACKAGE_OVERRIDE_FILE` 让 Buildroot 使用 `bsp/local.mk` 中的本地源码覆盖，例如 Linux 源码来自 `src/linux-friedegg`。`BSP_KERNEL_CROSS_COMPILE` 指向旧 Linaro 4.9 工具链，供 Linux 4.1 内核和外置 `.ko` 使用。

## `buildscripts/dtb.sh`

用途：只编译并部署默认 DTB。

依赖：

- `buildroot/.config` 已存在；不存在时会套用 BSP defconfig。
- 已有 Linux 构建树，通常是 `buildroot/output/build/linux-custom`。
- `BSP_KERNEL_CROSS_COMPILE` 可用。

输入：

- DTS 源码：`src/linux-friedegg/arch/arm/boot/dts/`
- 目标：`TARGET_DTB`，默认 `imx6ull-friedegg-emmc.dtb`

Buildroot 中间目录：

- 使用 `buildroot/output/build/linux-custom`
- 如果 `bsp/local.mk` 中有 `LINUX_OVERRIDE_SRCDIR`，脚本会先触发 `linux-rsync`

输出和部署范围：

- 复制构建出的 DTB 到 `buildroot/output/images/$TARGET_DTB`
- 再复制到 `TFTP_DIR=<tftp-dir>`

不会做什么：

- 不重新编译 `zImage`
- 不重新生成 `rootfs.tar`
- 不清理 NFS rootfs
- 不检查 TFTP 上旧文件 hash

## `buildscripts/linux_rebuild.sh`

用途：重编 Linux 非 DTS 改动并部署 `zImage`。

依赖：

- `buildroot/.config`
- Linux config 已经按需要 reset 或保存
- 旧内核工具链 `BSP_KERNEL_CROSS_COMPILE`

输入：

- Linux 源码：通常由 `bsp/local.mk` 指到 `src/linux-friedegg`
- Buildroot Linux 包配置：`buildroot/.config`

Buildroot 中间目录：

- `buildroot/output/build/linux-custom`
- Buildroot 目标：`linux-rebuild`

输出和部署范围：

- `buildroot/output/images/zImage`
- 复制到 `TFTP_DIR=<tftp-dir>`

不会做什么：

- 不部署 DTB
- 不更新 NFS rootfs
- 不重读 `bsp/configs/linux.config`；需要先运行 `./buildscripts/config.sh reset linux`

## `buildscripts/pkg_redeploy.sh <pkg>`

用途：重编一个 BSP local 包并增量部署它安装到 rootfs 的文件。

依赖：

- 包定义存在：`bsp/package/<pkg>/<pkg>.mk`
- 包已在 `buildroot/.config` 中启用
- 对 kernel-module 包，需要 Linux 构建树和旧内核工具链可用

输入：

- 包源码：由 `<PKG>_SITE` 指定，常见是 `src/<pkg>`；少数包名和源码目录会按历史命名略有不同，例如 `imx6-monitor` 对应 `src/imx6_monitor`
- 包构建规则：`<PKG>_BUILD_CMDS`、`<PKG>_INSTALL_TARGET_CMDS`、`kernel-module` 或 `qmake-package`

Buildroot 中间目录：

- Buildroot local package 会把源码同步到 `buildroot/output/build/<pkg>-...`
- `.ko` 包使用 `kernel-module` infra，并依赖 `buildroot/output/build/linux-custom`
- 用户态 test/app 使用 Buildroot target toolchain：`TARGET_CC`、`TARGET_CFLAGS`、`TARGET_LDFLAGS`

执行流程：

```bash
make <pkg>-dirclean
make <pkg>
```

输出和部署范围：

- 包安装文件先进入 `buildroot/output/target`
- 脚本读取 `buildroot/output/build/<pkg>-.../.files-list.txt`
- 只复制该包拥有的文件到 `NFS_DIR=<nfs-dir>`
- 写入简化 manifest：`buildroot/output/images/deploy-manifests/<pkg>.files`

不会做什么：

- 不生成 `rootfs.tar`
- 不清空 NFS rootfs
- 不自动删除该包曾经部署过、现在不再安装的旧文件
- 不重新编译或部署 DTB

常用包：

```bash
./buildscripts/pkg_redeploy.sh ap3216c
./buildscripts/pkg_redeploy.sh ov5640
./buildscripts/pkg_redeploy.sh gt9147
./buildscripts/pkg_redeploy.sh imx6-monitor
./buildscripts/pkg_redeploy.sh imx6-qt5-demo
```

## `buildscripts/pkg_clean_stale.sh <pkg>`

用途：显式清理某个包在 NFS rootfs 中的旧文件。

依赖：

- 上次运行 `pkg_redeploy.sh <pkg>` 后留下的 `deploy-manifests/<pkg>.files`
- `NFS_DIR=<nfs-dir>` 指向当前板端使用的 NFS rootfs

输入：

- 上次部署 manifest
- 当前 `.files-list.txt`；如果包已删除、已禁用、构建目录不存在或 `.files-list.txt` 不存在，当前文件集合按空处理

输出和部署范围：

- 删除“上次属于该包、本次不再属于该包”的 NFS 文件
- 更新该包 deploy manifest

不会做什么：

- 不清理 `output/target` 内部残留
- 不删除其他包拥有的文件
- 不处理 rootfs overlay 残留

适用场景：

- 包安装路径改名
- 测试程序改名
- `.ko` 文件改名
- 包已经从 `bsp/package/` 删除，但上次部署到 NFS 的文件还在

## `buildscripts/rootfs_redeploy.sh`

用途：重新生成 rootfs 镜像并全量刷新 NFS rootfs。

依赖：

- `buildroot/.config`
- Buildroot 输出目录能完成当前配置下的默认构建
- `NFS_DIR=<nfs-dir>` 安全有效

输入：

- `buildroot/output/target`
- Buildroot packages
- BSP local packages
- kernel modules
- `bsp/rootfs_overlay`

Buildroot 中间目录：

- `buildroot/output/target` 是组装目录，不等于 NFS rootfs
- `buildroot/output/images/rootfs.tar` 是 target-finalize 后生成的 rootfs image

输出和部署范围：

- 生成或更新 `buildroot/output/images/rootfs.tar`
- 清空 `NFS_DIR=<nfs-dir>` 一级内容
- 解包 `rootfs.tar` 到 NFS rootfs

不会做什么：

- 不执行 `make clean`
- 不保证清除 `output/target` 中已经残留的旧文件
- 不部署 TFTP 里的 `zImage` 或 DTB

## `buildscripts/all_rebuild.sh`

用途：最强清理路径，适合配置切换、libc/toolchain/rootfs 大改后重建。

依赖：

- BSP 固化配置存在：
  - `bsp/configs/imx6ull_friedegg_emmc_defconfig`
  - `bsp/configs/busybox.config`
  - `bsp/configs/linux.config`
- 旧内核工具链可用
- `NFS_DIR=<nfs-dir>`、`TFTP_DIR=<tftp-dir>` 安全有效

执行流程：

```bash
make imx6ull_friedegg_emmc_defconfig
make clean
make
```

输出和部署范围：

- `buildroot/output/images/zImage` -> TFTP
- `buildroot/output/images/imx6ull-friedegg-emmc.dtb` -> TFTP
- `buildroot/output/images/rootfs.tar` -> 清空后解包到 NFS

不会做什么：

- 不删除 Buildroot 下载缓存
- 不执行 `make distclean`
- 不保留 NFS rootfs 中手工放进去但不在 rootfs.tar 里的文件

## `buildscripts/config.sh`

用途：维护三类固化配置。

命令：

```bash
./buildscripts/config.sh status
./buildscripts/config.sh save buildroot|busybox|linux|all
./buildscripts/config.sh reset buildroot|busybox|linux|all
```

Buildroot 配置：

```bash
cd buildroot
make BR2_EXTERNAL=../bsp BR2_PACKAGE_OVERRIDE_FILE=../bsp/local.mk menuconfig
cd ..
./buildscripts/config.sh save buildroot
./buildscripts/config.sh reset buildroot
```

固化文件是 `bsp/configs/imx6ull_friedegg_emmc_defconfig`。

BusyBox 配置：

```bash
cd buildroot
make BR2_EXTERNAL=../bsp BR2_PACKAGE_OVERRIDE_FILE=../bsp/local.mk busybox-menuconfig
cd ..
./buildscripts/config.sh save busybox
./buildscripts/config.sh reset busybox
```

固化文件是 `bsp/configs/busybox.config`。

Linux 配置：

```bash
cd buildroot
make BR2_EXTERNAL=../bsp BR2_PACKAGE_OVERRIDE_FILE=../bsp/local.mk linux-menuconfig
cd ..
./buildscripts/config.sh save linux
./buildscripts/config.sh reset linux
```

临时配置文件是 `buildroot/output/build/linux-custom/.config`

固化文件是 `bsp/configs/linux.config`。

`status` 会比较当前临时配置和 BSP 固化配置。`reset` 会丢弃对应临时配置变化并重新加载固化配置。`save` 会把当前临时配置写回 `bsp/configs/`。

## Buildroot 目录关系

`src/<pkg>`：

- 人直接编辑的本地源码目录
- 由 `bsp/package/<pkg>/<pkg>.mk` 的 `<PKG>_SITE` 指向

`buildroot/output/build/<pkg>-...`：

- Buildroot 真正执行构建的包目录
- local package 会从 `src/<pkg>` rsync 到这里
- `<pkg>-dirclean` 会删除这个包构建目录和 stamp，让下次重新同步/配置/编译

`buildroot/output/build/linux-custom`：

- Buildroot Linux 包构建树
- 外置 `.ko` 的 `kernel-module` infra 使用这个目录的内核配置、符号和 `kernelrelease`
- Linux 4.1 和外置 `.ko` 使用 `BSP_KERNEL_CROSS_COMPILE` 指向的旧 Linaro 4.9

`buildroot/output/target`：

- Buildroot 的 rootfs 组装目录
- 包的 `INSTALL_TARGET_CMDS` 把文件装到这里
- `pkg_redeploy.sh` 从这里复制包文件到 NFS
- 它不是最终 NFS rootfs，也不保证包删除后自动清空旧安装文件

`buildroot/output/images/rootfs.tar`：

- target-finalize 之后生成的 rootfs 镜像
- 内容来自 BusyBox、Buildroot packages、BSP local packages、kernel modules 和 rootfs overlay
- `rootfs_redeploy.sh` 以它为输入刷新 NFS

`NFS_DIR=<nfs-dir>`：

- 板子启动后看到的 NFS rootfs
- `pkg_redeploy.sh` 只增量复制包文件
- `rootfs_redeploy.sh` 和 `all_rebuild.sh` 会清空后解包 `rootfs.tar`

## 残留处理

默认包重部署只增量复制，不自动删除旧文件。

包源码旧文件或旧 stamp：

```bash
./buildscripts/pkg_redeploy.sh <pkg>
```

脚本内部会执行 `<pkg>-dirclean`，清掉 `output/build/<pkg>-...` 后重建。

NFS 中包旧文件：

```bash
./buildscripts/pkg_clean_stale.sh <pkg>
```

它只删除上次 manifest 记录过、当前 `.files-list.txt` 不再记录的文件。

`output/target` 中旧安装文件：

- Buildroot 包级清理不总能完全清掉旧安装路径
- 必要时使用 `./buildscripts/rootfs_redeploy.sh` 刷新 NFS
- 如果 `output/target` 自己已经残留，使用 `./buildscripts/all_rebuild.sh`

rootfs overlay 删除后的旧文件：

- overlay 新增或修改后，通常运行 `./buildscripts/rootfs_redeploy.sh`
- overlay 删除后，旧文件可能已经留在 `output/target`
- 优先用 `./buildscripts/all_rebuild.sh` 做干净重建

禁用包后旧文件仍存在：

- `buildroot/.config` 禁用包不一定删除 `output/target` 或 NFS 里的旧文件
- 推荐流程：

```bash
./buildscripts/config.sh reset buildroot
./buildscripts/all_rebuild.sh
```

包重命名：

```bash
./buildscripts/pkg_clean_stale.sh <old-pkg>
./buildscripts/pkg_redeploy.sh <new-pkg>
```

## 新增 BSP local 驱动包

准备源码目录，例如：

```text
src/foo_drv/
  Makefile
  foo.c
  foo_test.c
```

注册只有 `.ko` 的包：

```bash
./buildscripts/build_and_deploy.sh drv add foo_drv ./src/foo_drv
./buildscripts/config.sh reset buildroot
./buildscripts/pkg_redeploy.sh foo_drv
```

注册同时安装用户态测试程序的包：

```bash
./buildscripts/build_and_deploy.sh drv add foo_drv ./src/foo_drv foo_test
./buildscripts/config.sh reset buildroot
./buildscripts/pkg_redeploy.sh foo_drv
```

注册会生成：

- `bsp/package/foo_drv/foo_drv.mk`
- `bsp/package/foo_drv/Config.in`
- `bsp/Config.in` 中的 source 行
- `bsp/configs/imx6ull_friedegg_emmc_defconfig` 中的 `BR2_PACKAGE_FOO_DRV=y`

## 板端验证提示

脚本不再提供主机侧校验子命令。需要确认板端实际效果时，先做通用系统检查，再进入对应 `src/<pkg>/README.md` 查看包级验证命令。

通用检查：

```sh
uname -r
cat /proc/device-tree/model
lsmod
dmesg | tail -n 80
```

包级入口：

- `src/ap3216c/README.md`：AP3216C IIO 设备、sysfs、事件和 `ap3216c_test`。
- `src/ov5640/README.md`：OV5640、CSI、V4L2 节点和 `ov5640_test`。
- `src/gt9147/README.md`：GT9147 input 设备和触摸事件。
- `src/imx6_monitor/README.md`：HTTP/MJPEG 监控服务。
- `src/imx6_qt5_demo/README.md`：Qt5 Widgets + linuxfb smoke test。
