# AP3216C 驱动总结笔记

## 驱动功能概述

`ap3216c.c` 是一个 I2C + regmap + IIO 驱动，用于 AP3216C 三合一传感器，源码中确认提供 ALS 环境光、PS 接近检测、IR 红外强度读取，以及 ALS/PS 阈值事件。用户接口主要由 IIO core 自动生成：`/sys/bus/iio/devices/iio:deviceX` 下的 direct mode sysfs 属性，以及 `/dev/iio:deviceX` 上通过 `IIO_GET_EVENT_FD_IOCTL` 取得的 IIO event fd。

硬件挂载位置由本仓库 DTS 确认：`imx6ull-friedegg-emmc.dts` 在 `&i2c1` 下声明 `ap3216c@1e`，compatible 为 `"alientek,ap3216c"`，地址为 `0x1e`，中断连接到 `GPIO1_IO01`。寄存器含义主要来自驱动内部宏命名；具体电气时序和量程解释仍以 datasheet 为准，本文未读取 datasheet。

## 1 目录 & 概括

### 1.1 总线类型与设备树

- **总线类型**：I2C 设备驱动，寄存器访问经由 regmap 的 I2C backend。
- **驱动入口**：`static struct i2c_driver ap3216c_driver`，通过 `module_i2c_driver(ap3216c_driver)` 注册；核心回调为 `ap3216c_probe()` 和 `ap3216c_remove()`。
- **ID / compatible**：`i2c_device_id` 为 `"ap3216c"`；OF match table 的 `.compatible` 为 `"alientek,ap3216c"`。
- **DTS 证据**：`src/linux-friedegg/arch/arm/boot/dts/imx6ull-friedegg-emmc.dts` 中 `ap3216c@1e` 位于 `&i2c1`，`reg = <0x1e>`，`interrupt-parent = <&gpio1>`，`interrupts = <1 IRQ_TYPE_LEVEL_LOW>`，`pinctrl-0 = <&pinctrl_ap3216c>`；`pinctrl_ap3216c` 将 `MX6UL_PAD_GPIO1_IO01` 复用为 `GPIO1_IO01`。
- **DTS 未发现资源**：未在 AP3216C 节点中发现 clocks、regulators、resets、DMA、ports/endpoints、额外 GPIO 属性；电源/时钟若存在，应由板级硬件常供或其他路径保证，本文标记为待确认。
- **probe 关键任务**：分配 `iio_dev` 和私有 `ap3216c_dev`；保存 `i2c_client`；初始化 8-bit reg / 8-bit val 的 regmap；初始化 mutex、默认阈值和 PS 中断算法；若 `client->irq > 0` 则申请 threaded IRQ；执行芯片 reset、配置中断清除方式、写阈值、清 pending 状态、进入 `als_ps_ir` 模式；填充 `iio_dev` 的 name、info、channels、direct mode 并注册 IIO 设备。
- **remove 关键任务**：加锁将芯片切到 power down；调用 `iio_device_unregister()` 注销 IIO 设备；调用 `regmap_exit()` 释放 regmap。IRQ 和 `iio_dev` 内存由 devm 框架随设备释放。
- **构建集成**：`bsp/package/ap3216c/Config.in` 定义 `BR2_PACKAGE_AP3216C`；`bsp/package/ap3216c/ap3216c.mk` 使用 local site `src/ap3216c`，安装 `/usr/bin/ap3216c_test`，并通过 Buildroot `kernel-module` 规则构建 `ap3216c.ko`。
- **源码注意点**：`regmap_init_i2c()` 失败时当前代码跳到统一 `err_regmap_exit`，该标签会执行 `regmap_exit(dev->regmap)`；此时 `dev->regmap` 是 `ERR_PTR`，疑似错误路径缺口，需代码修复或板端/内核行为确认。

## 2 接口 / 回调展开讲解

### 2.1 操作 [I2C/OF bind: probe]

- **触发来源**：DTS 中 `"alientek,ap3216c"` 的 I2C 设备被创建后，由 I2C core 匹配 `ap3216c_of_match` 或 `ap3216c_id`，调用 `ap3216c_probe()`。I2C core 的完整匹配路径本次未展开，按内核惯例推测。
- **内核调用路径**：I2C device bind -> `ap3216c_driver.probe` -> `ap3216c_probe()`；驱动注册入口为 `module_i2c_driver(ap3216c_driver)`。
- **Core 的关键处理**：I2C core 负责根据 DTS `reg = <0x1e>` 建立 `i2c_client`，根据 `interrupts` 填充 `client->irq`；IIO core 在后续 `iio_device_register()` 中创建 sysfs、event set 和 `/dev/iio:deviceX` 字符设备。
- **驱动回调实现分析**：probe 先 `devm_iio_device_alloc()` 分配 `iio_dev` 和私有数据，通过 `iio_priv()` 取得 `struct ap3216c_dev`；保存 `client` 到私有结构，并用 `i2c_set_clientdata()` 保存 `indio_dev`。随后创建 8-bit register/8-bit value regmap，初始化 mutex、默认阈值和默认 `hysteresis` PS 中断算法。若 `client->irq > 0`，申请 `IRQF_ONESHOT | IRQF_TRIGGER_LOW` 的 threaded IRQ。`ap3216c_reginit()` 负责芯片 reset、配置 read-to-clear、中断算法、阈值、清 pending 状态并进入 `als_ps_ir`。最后设置 `indio_dev->info`、`channels`、`INDIO_DIRECT_MODE` 并注册 IIO。
- **硬件操作与寄存器路径**：`regmap_write(AP3216C_SYSTEM_CONFIG, AP3216C_MODE_SW_RESET)` 后 `mdelay(50)`；写 `AP3216C_INT_CLEAR_MANNER = AP3216C_INT_CLEAR_BY_READ`；写 `AP3216C_PS_INT_MODE`；写 ALS/PS 阈值寄存器；读取 ALS/PS 数据寄存器清 pending；写 `AP3216C_SYSTEM_CONFIG` 进入 `AP3216C_MODE_ALS_PS_IR`。
- **要点 / 限制**：当前 IIO 模式是 `INDIO_DIRECT_MODE`，不是 buffer/trigger 采样流。没有 IRQ 时 direct read 仍可用，但 enable event 会返回 `-ENODEV`。疑似缺口：`regmap_init_i2c()` 返回 `ERR_PTR` 时统一错误路径会调用 `regmap_exit()`。
- **待补充项**：继续读 I2C core 的 OF 匹配、`client->irq` 填充路径；结合 datasheet 确认 reset 后寄存器默认值和 20/50/100 ms 延时依据。

### 2.2 操作 [I2C remove/unbind: remove]

- **触发来源**：模块卸载、设备解绑或驱动 unbind。
- **内核调用路径**：I2C core -> `ap3216c_driver.remove` -> `ap3216c_remove()`；I2C core 细节待查。
- **Core 的关键处理**：IIO core 的 `iio_device_unregister()` 会删除 device/cdev/debugfs，禁用 buffer，令 `indio_dev->info = NULL`，唤醒 event/buffer waitqueue，并释放 sysfs/buffer 资源。devm 框架负责释放 probe 中申请的 devm IRQ 和 devm IIO 内存。
- **驱动回调实现分析**：remove 通过 `i2c_get_clientdata()` 拿回 `indio_dev`，再通过 `iio_priv()` 回到私有结构。加锁调用 `ap3216c_set_mode(...POWER_DOWN)`，随后注销 IIO 设备并 `regmap_exit()`。
- **硬件操作与寄存器路径**：写 `AP3216C_SYSTEM_CONFIG` 的 mode 位为 `AP3216C_MODE_POWER_DOWN`，并等待 20 ms。
- **要点 / 限制**：remove 未检查 `ap3216c_set_mode()` 返回值；卸载路径主要追求关断和资源回收。若 regmap/I2C 已异常，power down 可能失败但不会阻止 unregister。
- **待补充项**：板端用 `rmmod ap3216c` 后确认 `/sys/bus/iio/devices/iio:deviceX`、`/dev/iio:deviceX` 和中断项是否消失。

### 2.3 操作 [IIO 设备名: cat name]

- **用户态行为**：`cat /sys/bus/iio/devices/iio:deviceX/name`，测试程序 `ap3216c_test scan` 也读取该属性来识别设备。
- **内核调用路径**：IIO core 创建通用 `name` sysfs 属性，返回 `indio_dev->name`。具体 `name` 属性创建路径本次未逐行展开，行为由 IIO core 和测试程序共同确认。
- **Core 的关键处理**：IIO core 负责将注册的 `iio_dev` 放到 IIO bus 下，并按 `iio:deviceX` 命名。
- **驱动回调实现分析**：驱动在 probe 中设置 `indio_dev->name = AP3216C_NAME`，宏值为 `"ap3216c"`，没有单独的 read callback。
- **硬件操作与寄存器路径**：无。
- **要点 / 限制**：这是用户态定位设备的首选入口；若存在多个 IIO 设备，不能假设一定是 `iio:device0`。
- **待补充项**：若板端枚举失败，先查 `dmesg`、I2C modalias、module alias 和 `ap3216c_test scan`。

### 2.4 操作 [ALS raw: cat in_illuminance_raw]

- **用户态行为**：`cat in_illuminance_raw` 或测试程序兼容的 `in_illuminance0_raw`。
- **内核调用路径**：sysfs show -> `iio_read_channel_info()` -> `indio_dev->info->read_raw()` -> `ap3216c_read_raw(..., IIO_CHAN_INFO_RAW)`，已查证 IIO core。
- **Core 的关键处理**：IIO core 根据 `iio_chan_spec` 生成属性名，将 `mask` 传给 `read_raw`，并用 `iio_format_value()` 把 `IIO_VAL_INT` 格式化为文本。
- **驱动回调实现分析**：驱动加 mutex，调用 `ap3216c_channel_read_mask()` 确认当前 mode 包含 ALS；若通道未激活返回 `-EAGAIN`。随后 `ap3216c_read_sample()` 读取 ALS 两个寄存器并拼成 16-bit raw。
- **硬件操作与寄存器路径**：`regmap_bulk_read(AP3216C_ALS_DATA_LOW, data, 2)` 读取 `0x0C/0x0D`，结果为 `data[1] << 8 | data[0]`。
- **要点 / 限制**：`power_down` 和 `ps_ir` mode 下 ALS 不 active，读取会失败；direct read 不保证每次都是新硬件采样周期。
- **待补充项**：datasheet 中 ALS 数据刷新周期和 mode 切换后的有效时间未确认。

### 2.5 操作 [ALS scale: cat/echo in_illuminance_scale]

- **用户态行为**：`cat in_illuminance_scale` 读取当前 ALS scale；`echo 0.315000 > in_illuminance_scale` 等写入合法 scale。
- **内核调用路径**：读路径为 sysfs show -> `iio_read_channel_info()` -> `ap3216c_read_raw(..., IIO_CHAN_INFO_SCALE)`；写路径为 sysfs store -> `iio_write_channel_info()` -> `write_raw_get_fmt()` -> `iio_str_to_fixpoint()` -> `ap3216c_write_raw(..., IIO_CHAN_INFO_SCALE)`。
- **Core 的关键处理**：IIO core 根据 `write_raw_get_fmt()` 返回的 `IIO_VAL_INT_PLUS_MICRO` 决定小数解析精度，把 `"0.315000"` 解析成 `val=0, val2=315000`，再交给驱动。
- **驱动回调实现分析**：读 scale 时驱动读取 `AP3216C_ALS_CONFIG` 的 range bits，索引 `als_scale_ap3216c[] = {315000, 78800, 19700, 4900}`，返回 `0 + val2/1000000`。写 scale 时只接受上述四个 `val2`，写入 range bits 后 `msleep(100)`，并通过 mutex 和读路径串行。
- **硬件操作与寄存器路径**：`regmap_update_bits(AP3216C_ALS_CONFIG, AP3216C_ALS_RANGE_MASK, index << AP3216C_ALS_RANGE_SHIFT)`，寄存器 `0x10`，mask `0x30`。
- **要点 / 限制**：写 scale 时只检查 `val2`，没有额外检查 `val` 必须为 0；当前 core 对合法输入会给 `val=0`。如果用户写非表内 scale，驱动返回 `-EINVAL`。
- **待补充项**：四个 scale 与 datasheet 量程 `20661/5162/1291/323 lux` 的对应关系需要 datasheet 复核。

### 2.6 操作 [ALS processed: cat in_illuminance_input]

- **用户态行为**：`cat in_illuminance_input` 或兼容属性 `in_illuminance0_input`。
- **内核调用路径**：sysfs show -> `iio_read_channel_info()` -> `ap3216c_read_raw(..., IIO_CHAN_INFO_PROCESSED)` -> `iio_format_value()`。
- **Core 的关键处理**：IIO core 负责把 `IIO_VAL_INT_PLUS_MICRO` 格式化成 `整数.微秒级小数` 风格文本。
- **驱动回调实现分析**：驱动要求通道类型为 `IIO_LIGHT`，并检查当前 mode 中 ALS active。随后读取 ALS raw，再读取 `AP3216C_ALS_CONFIG` 的 range bits，计算 `lux_micro = raw * scale_micro`，用 `div_u64_rem()` 拆成 `val` 和 `val2`。
- **硬件操作与寄存器路径**：读取 ALS 数据寄存器 `0x0C/0x0D`；读取 ALS config `0x10`。
- **要点 / 限制**：processed 值由驱动即时换算，不是硬件直接给出的 lux 寄存器。mode 或 scale 刚切换后，第一帧可能仍受旧采样影响，需板端验证。
- **待补充项**：环境光稳定条件下，用 `ap3216c_test test2` 验证四个 scale 的 processed 变化。

### 2.7 操作 [IR raw: cat in_intensity_ir_raw]

- **用户态行为**：`cat in_intensity_ir_raw` 或兼容属性 `in_intensity0_ir_raw`。
- **内核调用路径**：sysfs show -> `iio_read_channel_info()` -> `ap3216c_read_raw(..., IIO_CHAN_INFO_RAW)`。
- **Core 的关键处理**：IIO core 根据 `IIO_INTENSITY` + `IIO_MOD_LIGHT_IR` 生成 IR 相关属性；属性命名细节已由测试程序兼容两个名称，core 命名规则未完整展开。
- **驱动回调实现分析**：驱动检查当前 mode 中 IR active，仅 `ps_ir` 或 `als_ps_ir` 可读。读取 `IR_DATA_LOW/HIGH`，若 low byte 的 overflow bit 置位，返回 `-EOVERFLOW`；否则拼成 10-bit 值。
- **硬件操作与寄存器路径**：`regmap_bulk_read(AP3216C_IR_DATA_LOW, data, 2)` 读取 `0x0A/0x0B`；bit7 是 overflow，low byte bit1:0 加 high byte 组成数据。
- **要点 / 限制**：overflow 时用户态 `cat` 常表现为 I/O error；这不是 sysfs 属性不存在，而是驱动主动返回错误。
- **待补充项**：需 datasheet 确认 IR overflow bit 的清除条件和强光场景。

### 2.8 操作 [PS raw: cat in_proximity_raw]

- **用户态行为**：`cat in_proximity_raw` 或兼容属性 `in_proximity0_raw`。
- **内核调用路径**：sysfs show -> `iio_read_channel_info()` -> `ap3216c_read_raw(..., IIO_CHAN_INFO_RAW)`。
- **Core 的关键处理**：IIO core 根据 `IIO_PROXIMITY` 通道生成 proximity raw 属性，并格式化 `IIO_VAL_INT`。
- **驱动回调实现分析**：驱动检查当前 mode 中 PS active，仅 `ps_ir` 或 `als_ps_ir` 可读。读取 `PS_DATA_LOW/HIGH`，解析 object bit、overflow bit 和 10-bit proximity raw；overflow 时返回 `-EOVERFLOW`。
- **硬件操作与寄存器路径**：`regmap_bulk_read(AP3216C_PS_DATA_LOW, data, 2)` 读取 `0x0E/0x0F`；raw 使用 high byte bit5:0 和 low byte bit3:0。
- **要点 / 限制**：`ps_object` 主要在 IRQ event 中决定 rising/falling 方向；普通 raw 读取只返回数值，不直接返回 object flag。
- **待补充项**：PS raw 与 object flag、阈值算法 zone/hysteresis 的关系需 datasheet 补充。

### 2.9 操作 [operating_mode_available: cat]

- **用户态行为**：`cat operating_mode_available`。
- **内核调用路径**：IIO ext-info sysfs show -> `iio_read_channel_ext_info()` -> `iio_enum_available_read()`，已查证 core。
- **Core 的关键处理**：`iio_enum_available_read()` 遍历 `iio_enum.items`，输出所有可选字符串。
- **驱动回调实现分析**：驱动通过 `IIO_ENUM("operating_mode", IIO_SHARED_BY_ALL, &ap3216c_operating_mode_enum)` 和手写 available ext-info 暴露该属性；items 为 `power_down`、`als`、`ps_ir`、`als_ps_ir`。
- **硬件操作与寄存器路径**：无。
- **要点 / 限制**：这是可写 mode 的白名单；用户态不应写表外字符串。
- **待补充项**：无。

### 2.10 操作 [operating_mode: cat/echo]

- **用户态行为**：`cat operating_mode` 读取当前 mode；`echo als_ps_ir > operating_mode` 切换 mode。
- **内核调用路径**：读路径 `iio_enum_read()` -> `ap3216c_get_operating_mode()`；写路径 `iio_enum_write()` 用 `sysfs_streq()` 匹配字符串后调用 `ap3216c_set_operating_mode()`。
- **Core 的关键处理**：IIO enum core 负责字符串到 enum index 的转换，驱动只接收 index。
- **驱动回调实现分析**：get 路径把 `dev->mode` 映射成 index。set 路径检查 index 范围，查 `ap3216c_mode_values[]` 得到寄存器 mode 值，加锁后调用 `ap3216c_set_mode()`。`ap3216c_set_mode()` 用 regmap update bits 写系统配置寄存器，更新 `dev->mode`，并等待 20 ms。
- **硬件操作与寄存器路径**：`AP3216C_SYSTEM_CONFIG` 寄存器 `0x00`，mode mask `0x07`；可写值为 `POWER_DOWN=0x00`、`ALS_ONLY=0x01`、`PS_IR_ONLY=0x02`、`ALS_PS_IR=0x03`。
- **要点 / 限制**：mode 决定 read_raw 的 active channel mask；inactive 通道返回 `-EAGAIN`。20 ms 是驱动固定等待，不等价于 datasheet 已证实的数据 ready。
- **待补充项**：建议后续实现或验证 per-channel ready timestamp，避免 mode 切换后第一帧旧数据争议。

### 2.11 操作 [PS interrupt_algorithm: available/read/write]

- **用户态行为**：`cat in_proximity_interrupt_algorithm_available`、`cat in_proximity_interrupt_algorithm`、`echo hysteresis > in_proximity_interrupt_algorithm`。
- **内核调用路径**：available 使用 `iio_enum_available_read()`；读写使用 `iio_enum_read/write()` -> `ap3216c_get_ps_int_algo()` / `ap3216c_set_ps_int_algo()`。
- **Core 的关键处理**：IIO enum core 负责字符串列表和 index 转换；属性挂在 PS 通道 ext-info，shared type 为 `IIO_SHARED_BY_TYPE`。
- **驱动回调实现分析**：支持 `zone` 和 `hysteresis` 两种值。set 路径更新 `AP3216C_PS_INT_MODE` bit0，成功后更新 `dev->ps_int_algo`，并读取 ALS/PS 数据寄存器清 pending event；清 pending 失败只打印 warning，最终仍返回 0。
- **硬件操作与寄存器路径**：`regmap_update_bits(AP3216C_PS_INT_MODE, AP3216C_PS_INT_ALGO_MASK, value)`，寄存器 `0x22`，mask `0x01`。
- **要点 / 限制**：算法影响 PS 硬件如何判定 object/阈值，中断方向在驱动中仍根据 `sample->ps_object` 映射为 rising/falling。
- **待补充项**：zone/hysteresis 的精确定义需 datasheet。

### 2.12 操作 [ALS event enable: events/in_illuminance_thresh_*_en]

- **用户态行为**：`cat events/in_illuminance_thresh_rising_en` / `echo 1 > ..._en`；falling 同理。
- **内核调用路径**：IIO event sysfs show/store -> `iio_ev_state_show()` / `iio_ev_state_store()` -> `ap3216c_read_event_config()` / `ap3216c_write_event_config()`。
- **Core 的关键处理**：event core 从 `iio_event_spec` 中解析 event type、direction 和 info；store 使用 `strtobool()` 解析 enable 值。
- **驱动回调实现分析**：驱动用 `ap3216c_event_bit()` 将 `IIO_LIGHT + THRESH + RISING/FALLING` 映射到 `AP3216C_EVENT_ALS_RISING/FALLING`。写 enable 时，如果要启用且 `dev->irq <= 0`，返回 `-ENODEV`。随后更新 `event_enable_mask`，调用 `ap3216c_program_event_thresholds()` 写硬件阈值；写失败则回滚 mask。成功后读取 ALS/PS 数据清 pending。
- **硬件操作与寄存器路径**：启用状态本身保存在软件 mask；硬件侧通过 `AP3216C_ALS_LOW_TH_*` 和 `AP3216C_ALS_HIGH_TH_*` 编程阈值。未启用 falling 时 low 使用 0；未启用 rising 时 high 使用 65535。
- **要点 / 限制**：硬件中断依赖有效 IRQ；没有 IRQ 时 sysfs event 属性仍可能存在，但 enable 会失败。
- **待补充项**：板端确认 `/proc/interrupts` 中 ap3216c 中断计数随光照阈值变化增长。

### 2.13 操作 [ALS event value: events/in_illuminance_thresh_*_value]

- **用户态行为**：`cat/echo events/in_illuminance_thresh_rising_value` 设置 high 阈值；falling value 设置 low 阈值。
- **内核调用路径**：IIO event sysfs show/store -> `iio_ev_value_show()` / `iio_ev_value_store()` -> `ap3216c_read_event_value()` / `ap3216c_write_event_value()`。
- **Core 的关键处理**：event core 将 value store 文本按 fixpoint 解析为 `val/val2`，并把 event type/direction/info 传给驱动；show 使用 `iio_format_value()` 输出。
- **驱动回调实现分析**：驱动只接受 `IIO_EV_TYPE_THRESH` + `IIO_EV_INFO_VALUE`，要求 `val >= 0 && val2 == 0`。ALS 范围为 `0..65535`，且 low 不能大于 high。写入前保存旧阈值；硬件写失败则回滚软件阈值。成功后清 pending。
- **硬件操作与寄存器路径**：低阈值写 `AP3216C_ALS_LOW_TH_LOW/HIGH` 即 `0x1A/0x1B`；高阈值写 `AP3216C_ALS_HIGH_TH_LOW/HIGH` 即 `0x1C/0x1D`，均为 16-bit little-endian 风格拆分。
- **要点 / 限制**：禁用某一方向时，驱动仍保存用户设置的阈值；真正写到硬件的阈值可能被 `program_event_thresholds()` 放宽。
- **待补充项**：datasheet 中 ALS threshold 比较是否包含等号未确认；当前驱动推送事件时使用 `raw > high` 和 `raw < low`。

### 2.14 操作 [PS event enable: events/in_proximity_thresh_*_en]

- **用户态行为**：`cat/echo events/in_proximity_thresh_rising_en`；falling 同理。
- **内核调用路径**：IIO event sysfs show/store -> `read_event_config` / `write_event_config`，与 ALS enable 共用驱动回调。
- **Core 的关键处理**：event core 根据 PS 通道的 `iio_event_spec` 生成 rising/falling enable 属性。
- **驱动回调实现分析**：驱动将 `IIO_PROXIMITY + THRESH + RISING/FALLING` 映射到 `AP3216C_EVENT_PS_RISING/FALLING`。enable 流程与 ALS 相同：要求 IRQ、更新 mask、写阈值、清 pending。
- **硬件操作与寄存器路径**：PS 任一方向启用时，`ap3216c_program_event_thresholds()` 写当前 `dev->ps_th.low/high`；若 PS event 全部关闭，则写默认宽范围 `0..1023`。
- **要点 / 限制**：PS 事件方向最终由 IRQ 样本中的 `ps_object` 决定；阈值寄存器负责影响硬件 object/interrupt 判定。
- **待补充项**：结合 datasheet 验证 zone/hysteresis 下 rising/falling 的真实硬件语义。

### 2.15 操作 [PS event value: events/in_proximity_thresh_*_value]

- **用户态行为**：`cat/echo events/in_proximity_thresh_rising_value` 设置 high 阈值；falling value 设置 low 阈值。
- **内核调用路径**：IIO event sysfs show/store -> `read_event_value` / `write_event_value`，与 ALS value 共用驱动回调。
- **Core 的关键处理**：同 ALS event value：解析整数 value，传递 channel/type/direction/info。
- **驱动回调实现分析**：PS 范围限制为 `0..1023`，low 不能大于 high。写入流程保存旧阈值、更新软件阈值、写硬件寄存器，失败回滚，成功后清 pending。
- **硬件操作与寄存器路径**：低阈值写 `AP3216C_PS_LOW_TH_LOW/HIGH` 即 `0x2A/0x2B`；高阈值写 `AP3216C_PS_HIGH_TH_LOW/HIGH` 即 `0x2C/0x2D`。low register 只写 bit1:0，高字节写 `value >> 2`；对应 10-bit 阈值拆分。
- **要点 / 限制**：驱动默认 PS low/high 为 `100/200`；这来自源码初始化，不代表 datasheet 推荐值。
- **待补充项**：实际物体靠近/远离时 raw、object bit 与阈值的关系需板端记录。

### 2.16 操作 [/dev/iio:deviceX: open + IIO_GET_EVENT_FD_IOCTL]

- **用户态行为**：测试程序先 `open("/dev/iio:deviceX", O_RDONLY)`，再 `ioctl(fd, IIO_GET_EVENT_FD_IOCTL, &event_fd)`，随后关闭原始 IIO fd。
- **内核调用路径**：`open` -> `iio_chrdev_open()`；`ioctl` -> `iio_ioctl()` -> `iio_event_getfd()` -> `anon_inode_getfd("iio:event", ...)`。
- **Core 的关键处理**：IIO char device open 使用 `IIO_BUSY_BIT_POS` 防止同一 IIO chrdev 被重复打开，并保存 `indio_dev` 到 `filp->private_data`。`IIO_GET_EVENT_FD_IOCTL` 创建只读 close-on-exec 的 event fd；event fd 自己也有 busy bit，成功后 reset event kfifo output。
- **驱动回调实现分析**：AP3216C 不实现 file_operations，也不直接处理 ioctl；它只通过 `iio_device_register()` 把 `iio_info` 和 event-capable channels 交给 IIO core。
- **硬件操作与寄存器路径**：open/ioctl 本身不访问硬件。
- **要点 / 限制**：`iio_event_getfd()` 若 `event_interface == NULL` 返回 `-ENODEV`；若 event fd 已打开会返回 `-EBUSY`。本驱动有 event specs，因此注册成功时 event interface 应存在。
- **待补充项**：板端用 `ap3216c_test irq` 验证 event fd 是否能打开。

### 2.17 操作 [event fd: poll/read]

- **用户态行为**：测试程序对 event fd 调 `poll(POLLIN)`，再 `read(event_fd, &event, sizeof(event))` 读取 `struct iio_event_data`。
- **内核调用路径**：`poll` -> `iio_event_poll()`；`read` -> `iio_event_chrdev_read()`；事件来源为驱动 IRQ 线程调用 `iio_push_event()`。
- **Core 的关键处理**：IIO event core 内部有 16 项 kfifo。`iio_push_event()` 在 event fd busy 时将 `{id,timestamp}` 写入 kfifo 并唤醒 waitqueue。read 路径支持阻塞等待；非阻塞 fd 在无数据时返回 `-EAGAIN`。
- **驱动回调实现分析**：AP3216C 推送的 event id 由 `IIO_UNMOD_EVENT_CODE(IIO_LIGHT/PROXIMITY, 0, IIO_EV_TYPE_THRESH, dir)` 生成；timestamp 来自 `iio_get_time_ns()`。
- **硬件操作与寄存器路径**：event fd read/poll 不访问硬件；硬件访问发生在 IRQ 线程中。
- **要点 / 限制**：如果 event fd 没打开，`iio_push_event()` 会因为 event interface busy bit 未置位而丢弃事件；这符合 IIO event 模型。
- **待补充项**：高频中断下 16 项 kfifo 是否会溢出未在本驱动处理；需压力测试。

### 2.18 操作 [硬件 IRQ: ap3216c_irq_thread]

- **触发来源**：DTS 中 GPIO1_IO01 level-low 中断，probe 中以 `IRQF_ONESHOT | IRQF_TRIGGER_LOW` 申请 threaded IRQ。
- **内核调用路径**：IRQ core -> threaded handler `ap3216c_irq_thread()`；IRQ core 的 mask/thread/wakeup 细节本次未展开。
- **Core 的关键处理**：`IRQF_ONESHOT` 保证 threaded handler 运行期间中断线被合适地屏蔽，避免 level IRQ 重入问题；该描述基于内核惯例，未展开 IRQ core 源码。
- **驱动回调实现分析**：线程加 mutex 后读取 `AP3216C_INT_STATUS`，只保留 ALS/PS 位并记录 `last_int_status`。若没有 status 直接返回。根据当前 mode 计算 active 通道；若无 active 通道，读取 ALS/PS 清 pending 后返回。否则读取 active 样本：ALS status 且 ALS active 时调用 `ap3216c_push_als_event()`；PS status 且 PS active 时调用 `ap3216c_push_ps_event()`。
- **硬件操作与寄存器路径**：读 `AP3216C_INT_STATUS` 即 `0x01`；随后读取 ALS/IR/PS active 数据寄存器。因为初始化将 `AP3216C_INT_CLEAR_MANNER` 设置为 `AP3216C_INT_CLEAR_BY_READ`，读取数据寄存器同时承担清 pending 的作用。
- **要点 / 限制**：ALS event 方向由驱动比较 raw 和阈值得出：`raw > high` 为 rising，`raw < low` 为 falling。PS event 方向由 `ps_object` 决定：object true 为 rising，否则 falling；PS overflow 时跳过 event 并限频 warning。
- **待补充项**：需要板端结合 `/proc/interrupts`、event fd 输出和物理遮挡/光照变化验证 status bit 与 event 方向。

## 3 子系统专用 API 补充

- **API / 结构体**：`struct iio_info`
  - **出现位置**：`ap3216c_info`。
  - **在本驱动中的作用**：把 IIO core 生成的 sysfs/event 操作分发到 `read_raw`、`write_raw`、event config/value 回调。
  - **学习要点**：读 IIO 驱动时先看 `iio_info`，它是用户态 sysfs 行为与驱动函数的总开关。

- **API / 结构体**：`struct iio_chan_spec`
  - **出现位置**：`ap3216c_channels`。
  - **在本驱动中的作用**：声明 ALS/PS/IR 三个通道、通道类型、寄存器地址、raw/scale/processed 能力、ext-info 和 event specs。
  - **学习要点**：IIO 属性名不是手写 sysfs 文件，而是 core 根据 channel type、modifier、info mask 和 event spec 生成。

- **API / 结构体**：`struct iio_event_spec`
  - **出现位置**：`ap3216c_als_events`、`ap3216c_ps_events`。
  - **在本驱动中的作用**：声明 ALS/PS 支持 threshold rising/falling，并分别具备 `value` 和 `enable` 属性。
  - **学习要点**：event spec 只声明接口；真正 enable、阈值读写和事件推送仍由 `iio_info` 回调和 IRQ 线程完成。

- **API / 结构体**：`IIO_ENUM` / `struct iio_enum` / `iio_enum_available_read`
  - **出现位置**：`ap3216c_operating_mode_enum`、`ap3216c_ps_int_algo_enum`、`ap3216c_ext_info`、`ap3216c_ps_ext_info`。
  - **在本驱动中的作用**：把字符串型 sysfs 属性映射到硬件 mode 或 PS interrupt algorithm。
  - **学习要点**：IIO enum set/get 收到的是 item index，不是字符串；字符串匹配由 core 处理。

- **API / 结构体**：`iio_device_register()` / `iio_device_unregister()`
  - **出现位置**：probe/remove。
  - **在本驱动中的作用**：注册/注销 IIO 设备；core 创建 debugfs、buffer sysfs、channel sysfs、eventset 和 cdev。
  - **学习要点**：本驱动使用手动 register/unregister，而不是 `devm_iio_device_register()`；因此 remove 必须显式 unregister。

- **API / 结构体**：`iio_push_event()` / `IIO_UNMOD_EVENT_CODE()`
  - **出现位置**：`ap3216c_push_als_event()`、`ap3216c_push_ps_event()`。
  - **在本驱动中的作用**：把 IRQ 中判断出的 ALS/PS threshold event 放入 IIO event kfifo，供 event fd 读取。
  - **学习要点**：event id 编码包含 channel type、event type、direction 和 channel number；用户态可解析 id 判断事件来源。

- **API / 结构体**：`IIO_GET_EVENT_FD_IOCTL`
  - **出现位置**：`ap3216c_test.c` 用户态测试程序；内核实现位于 IIO core 的 `iio_ioctl()`。
  - **在本驱动中的作用**：用户态通过 `/dev/iio:deviceX` 获取专门的 event fd；驱动本身不实现 ioctl。
  - **学习要点**：IIO event 是 sysfs 配置 + event fd 读取的组合，不是传统驱动私有 ioctl。
