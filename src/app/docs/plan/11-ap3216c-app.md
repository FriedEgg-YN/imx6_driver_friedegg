# 11 AP3216C App：周期采样到 Widgets 展示

> 本阶段组合 [09 Worker 线程](09-qt-worker-thread.md) 与 [10 AP3216C Backend](10-ap3216c-backend.md)，范围服从 [SPEC](../../SPEC.md)：Start/Stop 和数值状态，不做曲线与完整配置。

## 目标与前置

目标：在 i.MX6ULL 上实现 AP3216C 单设备页面，显示 availability、lux、ALS/IR/PS raw、更新时间和错误；读失败时 GUI 仍响应。

前置：backend 单次读取通过；理解 Page/Controller/Service/Worker 边界和 queued signal。

## 最低必懂模型

- Page 只发 `startRequested/stopRequested` 并渲染 ViewState，不知道 sysfs 路径规则。
- Controller 在 GUI 线程把 typed sample 转成 `Ap3216cViewState`；Service 是跨线程窄门面；SensorWorker 的 QTimer 在 I/O 线程触发 backend。
- Start/Stop 控制周期采样，不等于设备数值 true/false。Start 请求被接受与第一帧成功是两个阶段。
- `availability`、字段 validity、timestamp/stale、error 必须显示成不同语义。
- 停止采样可保留“最后成功值”供观察，但必须标注 stopped/stale；设备失败不可伪装成 lux 0 或 raw 0。

## 数据流、线程与所有权

```text
GUI: Page -> Controller -> SensorService
                              |
                              | queued startAp3216c
                              v
I/O:                   SensorWorker QTimer -> Ap3216cBackend
                              |
                              `-- Ap3216cSample (value copy) --queued--> GUI
```

Page/Controller/Service 属于 GUI 线程；SensorWorker/backend/timer 属于进程级 Sensor I/O 线程。CompositionRoot 拥有 Service/Worker 线程；页面关闭只取消自己的订阅/采样意图，不直接 delete Worker。

## 分步手写任务

1. 画 480x272 页面草图：顶部状态，中央两列数值，底部 Start/Stop/Back，避免滚动和复杂图表。
2. 定义 `Ap3216cViewState`：sampling、availability、各显示值/valid、updated text、stale、error、按钮 enabled。
3. Page 构造 Widgets 和 layout；按钮只 emit intent，`render(state)` 统一更新。
4. Controller 连接 Service sample signal；先验证手工注入 sample 的正常/字段缺失/设备错误渲染。
5. Service 将 Start/Stop queued 给 Worker；Worker 幂等启动一个 500-1000 ms timer。
6. 每次 timeout 调 backend 一次并发 typed sample；禁止在 GUI timer 中读取 sysfs。
7. Controller 用 GUI 业务 timer 或当前时钟判 stale；不要修改原 sample 冒充新数据。
8. 实现 deactivate：禁用操作、提交 stop、收到 stopped 后通知 Shell 可销毁页面。

## 关键 Qt/C++ 片段

```cpp
connect(page, &Ap3216cPage::startRequested,
        controller, &Ap3216cController::start);
connect(service, &SensorService::ap3216cSampleReady,
        controller, &Ap3216cController::onSample);
connect(controller, &Ap3216cController::viewStateChanged,
        page, &Ap3216cPage::render);
```

渲染必须先看 validity：

```cpp
luxLabel_->setText(state.luxValid
    ? QString::number(state.lux, 'f', 2)
    : QStringLiteral("--"));
statusLabel_->setText(state.availabilityText);
errorLabel_->setText(state.error);
```

练习：停止后显示“Stopped，last update 3s ago”；超过 stale 阈值后值变灰且带 stale，不把它改成 0。

## 旧实现：可参考与不能照搬

可参考 `../../../imx6_smart_monitor/qt/apps/ap3216c_test/ap3216c_test_window.cpp` 的最小字段布局和 Start/Stop 交互。

不能照搬：旧页面持有 device，并由 GUI 线程 `QTimer` 直接 `readSample()`；失败后只更新部分 label，可能让旧数值看起来仍然有效。新页面必须通过 Service/Worker，且一次 ViewState 原子描述有效性与错误。

## 检查点

- 连续点 Start 采样频率不翻倍；Stop 后不再读 sysfs。
- 读文件期间拖动/点击仍响应。
- 所有 Widget 更新都在 GUI 线程。
- 单字段失败只显示该字段 `--`；设备缺失显示 Unavailable。
- Back 先 deactivate，stopped 后销毁，不在 GUI 无限 wait。

## 常见错误

- Page include `ap3216c_backend.h` 或直接打开 sysfs。
- Start 按钮直接启动 GUI `QTimer` 做 I/O。
- error 时执行 `luxLabel->setText("0")`，误导业务和用户。
- 只在成功时更新 UI，失败时遗留上次 Ready 和数值。
- 用 `isVisible()` 代替明确 activate/deactivate 生命周期。
- 每个页面创建独立 SensorWorker，破坏进程级服务所有权。

## 正常、缺失与失败验收

| 场景 | 预期 |
| --- | --- |
| 正常 | availability=Available，字段和更新时间周期更新 |
| 设备缺失 | 页面可进入和退出，显示 Unavailable/错误，所有值 `--` |
| 读取/解析失败 | Error 或部分 invalid；不显示假 0，Start/Stop 仍可用 |

## 完成标准

- AP3216C App 在 480x272 可操作，完成 Start/Stop/Back。
- GUI 无周期 sysfs I/O，Worker thread 日志可证明调用位置。
- 正常、缺失、失败三类板端结果均有记录。
- 能用三分钟讲清 `IIO sysfs -> backend -> Worker -> Service -> Controller -> Page`。
