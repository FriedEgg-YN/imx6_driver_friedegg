# 13 LD2410C App：类型化 presence 与接口状态展示

> 本阶段把 [12 LD2410C ABI](12-ld2410c-abi.md) 接入 Qt Worker 架构。第一版只展示读取链路和少量已验证可回读配置，服从 [SPEC](../../SPEC.md)。

## 目标与前置

目标：实现 LD2410C 单设备页面，显示 availability、presence、目标状态、运动/静止距离与能量，以及 misc、OUT/input、UART 分接口状态；错误时不显示假“无人”。

前置：完成 ABI harness；完成 [09 Worker 线程](09-qt-worker-thread.md)；明确页面生命周期与异步 stop。

## 最低必懂模型

- Page 只渲染 `Ld2410ViewState`，不 include UAPI、不开 `/dev`、不做 ioctl。
- SensorWorker 在 I/O 线程拥有 backend、fd 和采样 QTimer；Service queued 接收 Start/Stop/基础配置请求并转发 typed 状态。
- `presenceValid=true,presence=false` 才是“无人”；invalid/unavailable 显示 Unknown/Error，并供 Smart Monitor 采用 fail-safe 规则。
- 接口探测和实时数据分开：UART available 不代表 misc state 可读，misc 可读也不代表 OUT/input 节点存在。
- Controller 只将 typed snapshot 转 ViewState；target enum 到展示文本可以在 UI adapter 中完成，但程序分支不用字符串。
- 配置请求包含 operation/result；`Accepted` 只表示同步请求已被接受，异步写后回读确认后才返回 `Succeeded`。失败使用 `IoError`、`InvalidArgument` 等具体错误码，不用 `Failed` 泛称。

## 数据流、线程与所有权

```text
GUI thread
Ld2410Page -> Ld2410Controller -> SensorService
     ^                                  |
     | view state                       | queued command
     `----------------------------------+
                                        v
Sensor I/O thread: SensorWorker QTimer -> Ld2410cBackend -> misc ioctl
                                        `-> optional UART/config
```

进程级 SensorService/Worker 可同时服务 AP3216C 与 LD2410C。页面/Controller 是前台生命周期；离开页面后断开或忽略旧页面结果，Worker 是否继续由明确订阅/owner 策略决定。第一版单前台可用简单 OwnerId，不实现通用 lease。

## 分步手写任务

1. 画 480x272 页面：状态与 presence 优先，距离/能量紧凑两列，接口状态一行，Start/Stop/Probe/Back。
2. 定义 ViewState：sampling、device availability、presence validity/value、target enum、距离/能量字段、三个接口状态、updated/stale、error、按钮状态。
3. 先手工注入四组 snapshot：有人、无人、report invalid、ioctl error，验证渲染不会混淆。
4. Page 只连接 intent；Controller 订阅 Service 的 probe/snapshot/operation result。
5. Worker Start 时打开 misc 并启动有界周期 timer；每次读取后发布完整快照。Stop 停 timer 并关闭或按进程策略保留 fd，但 owner 必须明确。
6. Probe 单独发布 `Ld2410Interfaces`，UI 分别显示 misc/input/UART available/error。
7. 增加 stale 检测：没有新有效 sequence 超过阈值时 presence 变 Unknown，不沿用旧 false/true。
8. 可选增加一个已验证基础配置控件；提交后禁用该控件，收到 readback result 再更新。
9. 实现 deactivate：停止页面 timer/请求，等待 Service 报 stopped/idle 后允许 Shell 删除 Page/Controller。

## 关键接口与不变量

```cpp
void Ld2410Controller::onSnapshot(const Ld2410Snapshot &sample);
```

关键不变量：`sample.presenceValid == false` 时必须发布 `Unknown`，不能沿用旧 presence，也不能写成 `Absent`。

## 旧实现：可参考与不能照搬

可参考 `../../../imx6_smart_monitor/qt/apps/ld2410_test/ld2410_test_window.cpp` 的 Probe/Realtime 字段组织、target 文本映射和基础控件范围；Linux 调用机制参考旧 `ld2410_device.cpp`。

不能照搬：旧窗口直接持有 device，GUI timer 每 500 ms 调 ioctl；读取失败只改状态 label，旧 presence/距离可能继续显示；配置页一次执行多项设置，未逐项可靠回读。新 App 必须异步读取、完整发布 ViewState，并将配置缩到已验证字段。

## 检查点

- 人进入/离开时 valid presence 正确变化；遮断数据链路显示 Unknown/Error。
- misc/input/UART 状态分别展示，不用一个总 Ready 覆盖细节。
- GUI 线程日志中没有 open/ioctl/poll/UART。
- 连续 Start 不重复开 fd/timer；Stop/Back 可重复。
- operation 的同步 `Accepted` 与异步最终 `Succeeded` 分开；失败结果使用 `IoError` 等具体错误码。

## 常见错误

- `if (readFailed) presence=false;`，把故障变成无人。
- Page 根据 `statusLabel->text()` 决定按钮或业务。
- 失败时只更新 error，不清除旧值的 valid 标志。
- 在 GUI 中 `poll()`，即使 timeout 只有 500 ms 也会周期卡顿。
- 为 misc、input、UART 各开一个线程，却没有实际阻塞证据。
- 配置发送成功即更新全部 UI，不等待回读。
- 页面析构后 queued lambda 仍捕获裸 `this`；连接应有 QObject context，并按生命周期断开。

## 正常、缺失与失败验收

| 场景 | 预期 |
| --- | --- |
| 正常 | present/absent 均有 valid 标志；target、距离、能量、时间更新 |
| 接口/设备缺失 | 分接口显示 Missing；主状态 Unavailable，presence=Unknown 而非 Absent |
| ioctl/UART/配置失败 | typed error 可见，旧字段标 invalid/stale；GUI 可 Stop、Back、重试 |

## 完成标准

- 480x272 页面可完成 Probe、Start/Stop、状态观察和 Back。
- Page 不依赖 Linux/UAPI/backend，fd 与 timer 只在 Sensor I/O 线程。
- present、absent、unknown、unavailable 四种语义均有板端或可控失败验收记录。
- Smart Monitor 可复用同一 `Ld2410Snapshot` 的 valid presence，不需要解析 UI 字符串。
- 高级工程模式、噪声标定、恢复出厂、波特率切换仍留在旧测试程序。
