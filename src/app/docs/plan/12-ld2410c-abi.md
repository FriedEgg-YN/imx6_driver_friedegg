# 12 LD2410C ABI：misc、OUT/input 与 UART 分工

> 第一版范围见 [SPEC](../../SPEC.md)：先做读取链路与接口可用性；只迁移已验证且可回读的少量配置。高级配置留在旧测试程序。

## 目标与前置

目标：建立 LD2410C 用户态 ABI 表，手写 misc `ioctl` 状态读取和节点探测，区分 presence=false 与读取失败；理解 OUT/input、misc、UART 的不同职责。

前置：完成 [09 Worker 线程](09-qt-worker-thread.md)；会用 `open/ioctl/read/poll/close`，理解 C struct ABI。可先阅读项目头文件 `../../../ld2410c/include/friedegg/ld2410c.h`。

## 最低必懂模型

- misc `/dev/ld2410c0`：主应用的结构化状态和配置入口；`LD2410C_IOC_GET_STATE` 返回 flags、target、距离、能量、计数和 sequence。
- OUT/input：雷达 OUT 引脚经 input subsystem 暴露事件，适合存在状态变化提示；它不替代结构化距离/能量快照。
- UART：雷达协议数据和配置通道；旧实现会设置 termios2 并绑定 line discipline。UART 配置可能阻塞，不应放 GUI 线程。
- `LD2410C_STATE_F_REPORT_VALID` 与 `LD2410C_STATE_F_OUT_VALID` 决定相关字段是否可解释。presence 的 `false` 只有在状态读取成功且来源有效时才表示无人。
- ioctl ABI 依赖同一 UAPI 头中的 command number、方向、结构体大小和字段布局；应用不要复制一份私有结构定义。
- fd 由打开它的 backend/Worker 独占并关闭；不可跨线程传 fd 给 Page。
- 配置必须写后逐项回读，只更新确认成功的字段；部分成功不能宣称整份配置已应用。

## ABI 表

| 接口 | 输入 | 输出 | 第一版用途 | 失败语义 |
| --- | --- | --- | --- | --- |
| `/dev/ld2410c0` + `GET_STATE` | state struct 地址 | target、距离、能量、flags、sequence | 周期快照/presence | open/ioctl errno -> unavailable/invalid |
| misc `read/poll` | timeout/buffer | 变化后的 state | 可选事件驱动优化 | timeout 不等于无人；错误独立上报 |
| `/dev/input/eventX` | input_event 读取 | OUT 变化 | 显示接口可用性/提示 | 节点缺失只说明该接口缺失 |
| UART `/dev/ttymxcX` | baud、line discipline、命令 | 协议报告/ACK | 必要探测、少量已验证配置 | attach/协议/超时错误 |
| `READ_CONFIG` | config struct 地址 | 当前配置 | 写后回读 | 失败时不覆盖已确认状态 |

实际节点名必须板端探测；示例中的 `X` 不是固定编号。

## 数据流、线程与所有权

```text
LD2410C UART -> tty/line discipline --+
LD2410C OUT  -> input event ----------+--> kernel driver -> misc ioctl
                                                   |
Sensor I/O thread: Ld2410cBackend owns fd -> Ld2410Snapshot value
```

第一版 AP3216C 与 LD2410C 共用 Sensor I/O 线程。若实测 UART 配置阻塞显著影响 presence 周期，再拆线程；不要先设计额外线程。backend 负责 errno 上下文，Worker 负责调用节奏，Controller 不碰 ABI。

## 分步手写任务

1. 从 UAPI 头抄写一张“符号名而非数值”的 ABI 表，标注每个 flag 控制哪些字段。
2. 板端探测 misc、input 和 UART，分别记录存在性；不要把“三者任一存在”等同于完整可用。
3. 定义 `Ld2410Snapshot`：DeviceStatus、reportValid、presenceValid、presence、target、距离/能量 validity、source、sequence、timestamp、error。
4. 用 RAII backend 管理 misc fd，deleted copy；`openDevice()` 重复调用幂等。
5. `GET_STATE` 前零初始化 struct；ioctl 成功后按 flags 转换，不直接无条件使用字段。
6. 实现一次读取 harness，分别打印 `present/absent/invalid/error`。
7. 可选实现有界 `poll(timeout)`；timeout 发布“本周期无新事件”或保持状态，但绝不能发布 absent。
8. 只在确认需要配置时实现一个可回读字段：write -> readback -> compare -> typed result。

## 关键 Qt/C++ 片段

```cpp
struct Ld2410Snapshot {
    DeviceStatus status;
    bool reportValid = false;
    bool presenceValid = false;
    bool presence = false;
    quint8 targetState = 0;
    quint16 movingDistanceCm = 0;
    quint8 movingEnergy = 0;
    quint64 sequence = 0;
    qint64 updatedAtMs = 0;
    QString source;
};
Q_DECLARE_METATYPE(Ld2410Snapshot)
```

```cpp
ld2410c_state raw = {};
if (::ioctl(fd_, LD2410C_IOC_GET_STATE, &raw) < 0)
    return makeIoError(errno);

snapshot.reportValid = raw.flags & LD2410C_STATE_F_REPORT_VALID;
snapshot.presenceValid = snapshot.reportValid ||
                         (raw.flags & LD2410C_STATE_F_OUT_VALID);
if (snapshot.presenceValid)
    snapshot.presence = decodePresence(raw);
```

`decodePresence()` 的具体规则必须与当前驱动 UAPI/旧已验证机制核对；不要仅凭一个未标有效的字段猜测。

## 旧实现：可参考与不能照搬

可参考 `../../../imx6_smart_monitor/sensors/ld2410_device.cpp` 的 misc open/ioctl、input 节点发现、termios2 与 line discipline 绑定，以及 state 字段转换。

不能照搬：旧 `readState()` 用 bool 同时承载调用成功，状态内部 validity 仍偏粗；旧 App 在 GUI 线程直接读 ioctl，并一次提交大量高级配置且缺少逐项可靠回读。新实现先做窄读取闭环，错误发布 invalid/unavailable；配置只做已验证字段并逐项确认。

## 检查点

- 能解释 misc、OUT/input、UART 各自解决什么，不说成三个等价入口。
- ioctl 失败后 `presenceValid=false`，而不是 `presence=false`。
- backend 析构关闭 fd，fd 不离开 Sensor I/O 线程。
- poll timeout、设备 absent、设备 error 是三个状态。
- 写配置失败或回读不一致时只报告对应字段失败。

## 常见错误

- 把 `/dev/input/event0` 或 UART 编号写死。
- UAPI struct 不零初始化，或在用户态重新定义导致布局漂移。
- 只检查 ioctl 返回值，不检查 `REPORT_VALID/OUT_VALID`。
- timeout 后发布无人，导致 Smart Monitor 提前进入 Cooldown。
- 在 GUI 线程 attach UART 或执行长配置。
- set 多字段中途失败后仍把 UI 全部改为新值。

## 正常、缺失与失败验收

| 场景 | 预期 |
| --- | --- |
| 正常有人/无人 | 两者均 `presenceValid=true`，presence 分别 true/false |
| 某接口缺失 | 分接口 availability；misc 缺失时主快照 unavailable，不能伪造无人 |
| ioctl/UART/解析失败 | typed error、invalid timestamp 不刷新；GUI 后续仍可重试/停止 |

## 完成标准

- ABI 表、数据流和 fd 所有权可脱离代码讲清。
- 板端可区分 present、absent、invalid、unavailable。
- harness 不需要 QApplication，错误包含操作和 errno 上下文。
- 只完成读取与必要探测；高级工程模式、标定、恢复出厂和波特率切换未迁移。
